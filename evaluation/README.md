# Оценка алгоритмов

[dataset.json](dataset.json) — запросы и ожидаемый результат. [evaluate.py](evaluate.py) прогоняет через них алгоритмы из `algo/config.py` и считает оценку. Запуск из корня репозитория, без зависимостей:

```bash
python3 evaluation/evaluate.py
python3 evaluation/evaluate.py --algorithms structured tfidf-char --details
python3 evaluation/evaluate.py --threshold 0.9 --json evaluation/report.json
```

`--catalog` позволяет проверить алгоритмы на каталоге, отредактированном в интерфейсе: скопируйте `/data/commands.json` из контейнера (`docker compose cp backend:/data/commands.json commands.json`) и передайте путь.

## Формат датасета

Запись ссылается на блоки по их `text`, а не по номеру: номера меняются при удалении блока.

```json
{"query": "включи свет на кухне и выключи телевизор в спальне", "kind": "несколько команд",
 "expect": ["включи свет на кухне", "выключи телевизор в спальне"]}
{"query": "ыключи свет на кухне", "kind": "неоднозначно",
 "alternatives": ["включи свет на кухне", "выключи свет на кухне"]}
{"query": "не включай свет", "kind": "отказ", "note": "отрицание"}
```

- `expect` — команды, которые нужно выбрать **уверенно**; несколько элементов — несколько команд в одном запросе.
- `alternatives` — уверенного ответа быть не должно, но эти блоки полезно показать среди кандидатов.
- Ни `expect`, ни `alternatives` — правильный ответ — отказ.
- `kind` — тип запроса для разбивки результата, `note` — пояснение для человека.

Скрипт сам проверяет, что все упомянутые блоки есть в каталоге.

## Что считается

**Уверенный ответ** — `decision = accept`, если алгоритм возвращает это поле; иначе — top-1 `score ≥ --threshold` (по умолчанию 0.8, как зелёная рамка в первом MVP). **Ответ алгоритма** — лучший блок каждой `command` или просто top-1.

| метрика | как считается | зачем |
|---|---|---|
| **ИТОГ** | среднее баллов по запросам (ниже) | одно число для сравнения |
| top-1, MRR | место ожидаемого блока среди запросов с одной командой | качество ранжирования |
| полнота@5 | доля ожидаемых блоков в первых пяти | годится ли список как кандидаты для следующего шага |
| верно увер. | доля запросов с `expect`, где алгоритм уверенно выбрал ровно их | польза без переспроса |
| безоп. отказ | доля запросов без `expect`, где уверенного ответа нет | умение не угадывать |
| опасных | число уверенных ответов, которые неверны или не должны были быть уверенными | главный риск: молча выполнить не то |
| p50, p95 мс | время одного вызова `search` после прогрева | задержка |

Балл запроса:

| запрос | алгоритм уверен и прав | алгоритм не уверен | алгоритм уверен, но не прав |
|---|---|---|---|
| с `expect` | 1 | 0.5 × доля ожидаемых в top-5 | 0 |
| без `expect` | — | 0.5 + 0.5 × доля `alternatives` в top-5 | 0 |

Так переспрос всегда лучше ошибки, а полезный список кандидатов лучше пустого.

## Результат на текущем каталоге

`python3 evaluation/evaluate.py` (137 запросов, 42 блока, порог 0.8):

| алгоритм | ИТОГ | top-1 | полнота@5 | верно увер. | безоп. отказ | опасных | p50 мс |
|---|---|---|---|---|---|---|---|
| levenshtein-combinations | 0.787 | 0.898 | 0.935 | 0.630 | 0.838 | 6 | ~150 |
| tfidf-char | 0.774 | 0.989 | 0.995 | 0.780 | 0.568 | 23 | ~0.9 |
| structured | 0.996 | 1.000 | 1.000 | 0.990 | 1.000 | 0 | ~0.4 |
| structured-morph | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 0 | ~0.4 |

Политика незнакомых слов (обращение — пропустить, после «в/на» или вместо объекта — отказ, остальное — уточнение) подняла `structured` на этом наборе с 0.966 до 1.000: раньше все семь запросов с обращением («привет, включи…») получали отказ.

Лемматизация (`structured-morph`, нужен `pip install -r backend/requirements.txt`) закрывает тип «словоформа»: 0.857 → 1.000. Без неё четыре запроса с глаголом на «-те» («откройте», «закройте», «найдите», «погасите») уходят в уточнение. Левенштейн по целой строке на этом типе получает 1.000: окончание меняет лишь пару символов длинной фразы. Пословному поиску окончания мешают сильнее, поэтому ему и нужна морфология.

Разрывные действия («поставь музыку на паузу» без отдельного alias) и эллипсис («включи свет на кухне, а в спальне выключи») добавили 6 запросов: на них прошлая версия `structured` теряла баллы (0.964 → 0.984 на этом наборе), Левенштейн по разрывным действиям — 0.333. Контрольный «выключи музыку свет на кухне» (два объекта без союза) уверенно не выбирается. Подсказки TF-IDF при пустом ответе на итог не влияют: решение остаётся отказом.

Состояния с целью («сделай музыку громче»), заполнители «тоже/ещё» и подсказки вместо списка всех блоков с тем же действием для незнакомого объекта («открой форточку») — ещё 8 запросов: на этом наборе `structured` 0.966 → 0.985, `structured-morph` 0.981 → 1.000. Контрольные «включи музыку тише» и «отмена музыку» уверенно не выбираются.

Синонимия действий (по ревью ментора) убрала из каталога блоки-дубли «зажги свет на кухне/в спальне» (44 → 42 блока): «зажги», «погаси», «вруби», «врубай», «зажгите» теперь работают для всех блоков через группы `GROUPS`. Фразовые методы синонимов вне блоков не знают: Левенштейн на типе «синоним» — 0.868. Явные антонимы (`OPPOSITE`) переводят в уточнение и не-слово-опечатки вида «выключть», которые раньше выбирались уверенно, если одно расстояние было меньше.

## Метаморфные тесты

[metamorphic.py](metamorphic.py) берёт каждую фразу датасета, меняет её так, что правильное поведение известно без разметки, и считает нарушения:

| отношение | что меняется | ожидание |
|---|---|---|
| перестановка каталога | блоки в другом порядке (3 перестановки, seed) | то же решение и те же выбранные блоки |
| вежливость и обращение | «пожалуйста …», «… пожалуйста», «привет …» | то же решение и те же блоки |
| добавлено «не» | «не …» | никогда не `accept` |
| опечатка-антоним | все однобуквенные опечатки слова, которые в пределах допуска и к нему, и к его антониму («включи» → «вкылючи») | никогда не `accept` |

Запросы с самоисправлением в последние два отношения не входят: изменение в отброшенной части правильно не мешает ответу. Настоящие слова («выключит», «включать») опечатками не считаются, если установлен pymorphy3.

```bash
python3 evaluation/metamorphic.py --details
```

Результат (5 622 проверки с установленным pymorphy3; без него опечаток-антонимов на 35 больше), число нарушений / проверок:

| алгоритм | перестановка каталога | вежливость и обращение | добавлено «не» | опечатка-антоним |
|---|---|---|---|---|
| levenshtein-combinations | 0 / 411 | 361 / 411 | 33 / 135 | 2124 / 4665 |
| tfidf-char | 0 / 411 | 155 / 411 | 95 / 135 | 2944 / 4665 |
| structured | 0 / 411 | 0 / 411 | 0 / 135 | 0 / 4665 |
| structured-morph | 0 / 411 | 0 / 411 | 0 / 135 | 0 / 4665 |

Фразовые методы проваливают именно то, ради чего эти отношения: «пожалуйста» сдвигает уверенность, «не включай» остаётся уверенным «включи», опечатку между «включи» и «выключи» они выбирают уверенно.

Тест `MetamorphicTests` в `backend/tests` требует 0 нарушений для `structured` и `structured-morph`. Отношения уже нашли то, что пропускал ручной датасет: при ничьей первый кандидат зависел от порядка блоков в каталоге; «привет включи» читалось как незнакомый объект «привет»; подсказки менялись от обращения.

Важно: датасет составлен автором `structured` одновременно с алгоритмом, поэтому его результат завышен. Добавляйте свои запросы — особенно те, на которых алгоритм ошибается — до того, как подстраивать под них код. Задержка зависит от компьютера.
