# Индекс команд и объектов — платформа алгоритмов

Локальный прототип, который показывает кандидатов для текстового запроса. Он не исполняет команду и не извлекает параметры вроде даты или времени.

## Модель данных

Единица хранения — **смысловой блок**: обязательный канонический текст `text` и необязательные варианты действия `actions` и объекта `objects`. В `actions` хранятся синонимы в начальной форме, а не словоформы; варианты объекта записываются в винительном падеже: `музыку`, `подсветку на кухне`.

```python
{
    'text': 'включи свет на кухне',
    'actions': ['включить', 'зажечь'],
    'objects': ['свет на кухне', 'кухонный свет', 'подсветку на кухне'],
}
```

Специальная команда обходится только обязательным полем:

```python
{'text': 'дальше'}
```

Пустая строка в `actions` имеет отдельный смысл: это форма **без действия**, которая позволяет получить сочетание `'' + 'тише'` → «тише». В интерфейсе такая форма показывается как `∅`; её же можно ввести в поле вариантов действия.

Стартовый список словарей находится в [backend/app/catalog.py](backend/app/catalog.py). Он же доступен алгоритму как обычный список; после редактирования через интерфейс актуальная копия сохраняется в JSON-файл Docker volume. Для этой небольшой модели база данных не нужна.

Сохранённые ранее данные автоматически не заменяются. Чтобы загрузить новый стартовый каталог, сохраните нужные изменения и нажмите «Загрузить пример»: эта кнопка заменяет текущий список целиком.

При запуске платформа загружает каталог в память и подготавливает индексы алгоритмов. Добавление, изменение, удаление команды, очистка и загрузка примера создают новый снимок каталога и пересобирают индексы один раз. Обычный запрос использует готовый снимок без чтения файла и проверки всего каталога на изменения. Если файл каталога изменить вручную, понадобится перезапуск платформы. Запрос, начавшийся до редактирования, завершится на старом снимке.

## Алгоритмы и контракт

Алгоритмы живут в корневой папке [algo](algo). Каждый метод находится в отдельном файле и содержит функцию `search(query, blocks)`. Она возвращает отсортированный массив словарей с тремя обязательными полями:

```python
{
    'index': 7,                       # индекс смыслового блока
    'text': 'включи кухонный свет',   # конкретная сработавшая форма
    'score': 0.94,                    # оценка от 0 до 1
}
```

Необязательные поля `decision` (accept · clarify · reject), `status`, `command` и `explain` позволяют методу сказать, уверен ли он, сколько команд в запросе и почему выбран блок; интерфейс их показывает. Подробности — [algo/README.md](algo/README.md).

В [algo/shared.py](algo/shared.py) лежат общие функции: нормализация, Левенштейн, генерация форм, токены, расстояние с перестановкой букв и нечёткий индекс удалений. В [algo/config.py](algo/config.py) зарегистрированы доступные методы: `id`, название, описание, Python-модуль и имя функции. Платформа сама загружает функцию и проверяет её контракт, поэтому добавление алгоритма не требует изменения `main.py`.

Алгоритмам передаётся снимок, совместимый со списком словарей; изменять его нельзя. При необходимости алгоритм может определить `prepare_index(blocks)` и сохранить подготовленные данные через `prepared_index` из `algo/shared.py`: платформа вызовет подготовку при создании снимка. Функции поиска также принимают обычный список для экспериментов, но для него индекс готовится заново при каждом вызове, поскольку такой список можно изменить. Кэш нормализации и лемматизации остаётся общим и не зависит от снимка.

Сейчас подключено три метода:

- `levenshtein-combinations` — для блока сравнивает канонический `text`, все пары `action + object` и все пары в обратном порядке `object + action`; выбирается форма с минимальным расстоянием;
- `tfidf-char` — косинус по символьным триграммам с весами IDF; выдаёт не более 10 блоков с оценкой от 0.5. Быстрее и терпимее к лишним словам, но смысла запроса тоже не видит;
- `structured` — находит в запросе действия, слова объектов и служебные слова, собирает из них команды и решает, можно ли выбрать уверенно. Понимает несколько команд («включи свет на кухне и выключи телевизор в спальне»), неполные названия, отрицание, самоисправление и не выбирает молча при опечатке между «включи» и «выключи». Если ничего не нашёл — подсказывает похожие формулировки от TF-IDF, оставляя решение отказом.

![Структурный индекс](docs/structured-algorithm.svg)

Лемматизация [pymorphy3](https://github.com/no-plagiarism/pymorphy3) находится в общих функциях: «включите» и «включи» сопоставляются с «включить». В словаре «включай» относится к другой лемме — «включать», поэтому явно заданные видовые пары приводят её к «включить» в контексте команд. Структурный алгоритм использует все словарные леммы для действий и объектов; Левенштейн и TF-IDF используют наиболее вероятную. Неизвестные слова не лемматизируются по догадке, сравнительные формы вроде «дальше» сохраняются. Зависимость ставится из [backend/requirements.txt](backend/requirements.txt).

Синонимы задаются для конкретного блока: свет можно «включить» или «зажечь», а кондиционер — только «включить». Группы действий и пары противоположностей в [algo/structured.py](algo/structured.py) помогают структурному алгоритму выявлять неоднозначность между антонимами, но не расширяют допустимые для блока действия. Комната остаётся частью объекта: «свет на кухне» — одна строка. Отдельных отношений допустимых пар действий и объектов пока нет: каждый блок описывает одну команду.

## Оценка

[evaluation/dataset.json](evaluation/dataset.json) — 138 запросов с ожидаемым результатом: точные, синонимы, порядок слов, опечатки, неполные названия, разрывные действия («поставь музыку на паузу»), словоформы («включите», «лампы»), лишние слова, обращения («привет, включи…»), несколько команд, неоднозначные и те, где правильный ответ — отказ. [evaluation/evaluate.py](evaluation/evaluate.py) прогоняет через них все алгоритмы и печатает таблицу: итоговый балл, top-1, полноту, долю опасных уверенных ответов и задержку.

```bash
python3 evaluation/evaluate.py --details
```

Метрики и формат записи — в [evaluation/README.md](evaluation/README.md).

Кроме ручных запросов есть метаморфные тесты ([evaluation/metamorphic.py](evaluation/metamorphic.py)): из каждой фразы датасета автоматически строятся тысячи вариантов — перестановка каталога, «пожалуйста» и обращение, «не», опечатка между антонимами — и проверяется, что ответ ведёт себя согласованно.

```bash
python3 evaluation/metamorphic.py --details
```

## Интерфейс

Интерфейс загружает алгоритмы из конфигурации. Можно выбрать от одного до трёх методов, ввести один запрос и получить отдельный вертикальный ранжированный список от каждого выбранного метода. Если метод возвращает необязательные поля, у списка появляется решение (уверенный выбор, уточнение, безопасный отказ), у блока — номер команды, статус и объяснение. Для каждого блока можно раскрыть библиотеку и отредактировать канонический текст, варианты действия и варианты объекта.

## Запуск

```bash
docker compose up --build
```

Откройте [localhost:8080](http://localhost:8080). Данные, добавленные через интерфейс, сохраняются между перезапусками контейнеров. Кнопка «Загрузить пример» заменяет их исходным списком из `catalog.py`.

Docker-образ backend сам ставит `backend/requirements.txt`. Для тестов и оценки вне Docker:

```bash
python3 -m pip install -r backend/requirements.txt
```

Тесты:

```bash
python3 -m unittest discover -s backend/tests
```
